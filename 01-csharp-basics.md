# 01 — C# Basics

This chapter covers program structure, how code is organized, console I/O, and basic syntax rules. If you've used Java, C++, or JavaScript, much of the syntax will feel familiar.

## Program structure: the full form vs top-level statements

The classic, explicit form of a C# program:

```csharp
using System;                         // import a namespace

namespace MyApp                       // your code's namespace
{
    class Program                     // every method lives in a type
    {
        static void Main(string[] args)   // the entry point
        {
            Console.WriteLine("Hello, World!");
        }
    }
}
```

Breaking it down:
- **`using System;`** — imports the `System` namespace so you can write `Console` instead of `System.Console`.
- **`namespace MyApp`** — a logical container that groups related types and prevents name clashes (like packages/modules elsewhere).
- **`class Program`** — C# has no free-floating functions; all code lives inside a type.
- **`static void Main(string[] args)`** — the entry point. The runtime calls this to start your program. `args` are command-line arguments.

### Top-level statements (modern, default)

Since C# 9, a file can skip the ceremony. The compiler wraps your statements in a hidden `Main`:

```csharp
Console.WriteLine("Hello, World!");
```

You can still access `args` (it's implicitly available), declare functions, and `return` an exit code. **Only one file** in a project may use top-level statements. Everything else is still classes/methods. We'll use top-level statements for small examples and the full form when defining real types.

> A subtle point: even with `ImplicitUsings` enabled, `System` is auto-imported, which is why `Console` "just works" without a visible `using System;`.

## Namespaces and `using`

Namespaces organize code. The BCL is full of them: `System`, `System.Collections.Generic`, `System.Linq`, `System.Text.Json`, etc.

```csharp
using System;
using System.Collections.Generic;     // for List<T>, Dictionary<,>
using System.Linq;                     // for LINQ methods

// File-scoped namespace (modern, preferred) — applies to the whole file,
// no extra indentation:
namespace MyCompany.MyApp;

class Customer { }
```

The older block form `namespace X { ... }` still works but file-scoped (`namespace X;`) is now standard.

**`global using`** (in any `.cs` file or generated by `ImplicitUsings`) imports a namespace across the entire project:

```csharp
global using System.Text.Json;
```

## Statements, blocks, and semicolons

- Statements end with `;`.
- Blocks are wrapped in `{ }`.
- Whitespace and newlines are insignificant (unlike Python). Indentation is for humans.

```csharp
int x = 5; int y = 10;   // legal but ugly — one statement per line, please
{
    // a block creates a scope; variables declared here die at the closing brace
    int temp = x + y;
    Console.WriteLine(temp);
}
// temp is not visible here
```

## Comments

```csharp
// single-line comment

/* multi-line
   comment */

/// <summary>
/// XML doc comment — shows up in IntelliSense and can generate docs.
/// </summary>
/// <param name="name">The person's name.</param>
/// <returns>A greeting.</returns>
string Greet(string name) => $"Hi {name}";
```

Use `///` doc comments on public APIs (methods, classes) — tooling reads them and teammates see them in autocomplete.

## Console input and output

```csharp
Console.WriteLine("This prints with a newline");
Console.Write("No newline. ");
Console.Write("Same line.\n");

Console.WriteLine("Enter your name:");
string? name = Console.ReadLine();      // reads a line; returns null at end-of-input
Console.WriteLine($"Hello, {name}!");
```

- `Console.WriteLine` writes a line; `Console.Write` writes without a newline.
- `Console.ReadLine()` reads a line of input as a `string?` (it can be null).

### String interpolation

The `$"..."` syntax embeds expressions directly:

```csharp
int age = 30;
string name = "Sam";
Console.WriteLine($"{name} is {age} years old.");
Console.WriteLine($"Next year: {age + 1}");
Console.WriteLine($"Price: {19.5m:C}");     // :C = currency format -> $19.50
Console.WriteLine($"Pi: {3.14159:F2}");     // :F2 = 2 decimal places -> 3.14
```

Format specifiers after `:` control display — `C` currency, `F2` fixed decimals, `N0` number with thousands separators, `P` percent, `X` hex, `yyyy-MM-dd` for dates. Prefer interpolation over string concatenation with `+`.

### Verbatim and raw strings

```csharp
// Verbatim string: backslashes are literal, good for file paths
string path = @"C:\Users\Sam\file.txt";

// Raw string literals (C# 11+): triple quotes, no escaping needed,
// great for JSON, SQL, HTML:
string json = """
    {
        "name": "Sam",
        "age": 30
    }
    """;

// Combine raw + interpolation with $$ (the number of $ = braces needed for holes):
string sql = $$"""
    SELECT * FROM Users WHERE Name = '{{name}}'
    """;
```

## Basic types preview

You'll meet these fully in Chapter 2, but you need them now:

```csharp
int count = 42;             // 32-bit integer
long big = 9_000_000_000;   // 64-bit integer (underscores are visual separators)
double price = 19.99;       // 64-bit floating point
decimal money = 19.99m;     // exact decimal — use for money (note the 'm' suffix)
bool isReady = true;        // true/false
char letter = 'A';          // single character (single quotes)
string text = "hello";      // text (double quotes)
```

## `var` — let the compiler infer the type

When the type is obvious from the right-hand side, use `var`:

```csharp
var count = 42;             // compiler knows it's int
var name = "Sam";          // string
var list = new List<int>();// List<int>

// var is still STATICALLY typed — this is NOT dynamic.
// count = "hello";        // compile error: can't assign string to int
```

`var` is purely a typing shortcut; the variable still has one fixed compile-time type. Teams vary on style: many use `var` when the type is evident (`var x = new Customer()`) and explicit types when it aids readability (`int total = Sum(...)`). Both are fine.

## Constants

```csharp
const double Pi = 3.14159;          // compile-time constant, must be set inline
const string AppName = "MyApp";
```

`const` values are baked in at compile time and can't change. For values fixed at runtime (e.g., from config), use `readonly` fields (Chapter 5).

## A slightly bigger first program

```csharp
Console.WriteLine("=== Tip Calculator ===");

Console.Write("Bill amount: ");
string? input = Console.ReadLine();

// Parse text to a number. TryParse is the safe way (Chapter 2 explains why).
if (decimal.TryParse(input, out decimal bill))
{
    decimal tip = bill * 0.18m;
    decimal total = bill + tip;
    Console.WriteLine($"Tip (18%): {tip:C}");
    Console.WriteLine($"Total:     {total:C}");
}
else
{
    Console.WriteLine("That wasn't a valid number.");
}
```

Run it, type `50`, and you should see a tip of $9.00 and total of $59.00. We'll unpack `TryParse`, `out`, and `if` in the next chapters.
